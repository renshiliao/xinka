五层一口炉

信卡熔炉的结构只有五层和一条回流通道：信卡库存知识、双闸管入口、心网连成网、保鲜管寿命、技能熔炼出成品——实战经验从下游回流，喂回上游。

五层各管什么

层部件管什么不过这层会怎样
① 信卡库md 六要表 + JSON 孪生知识本体：源/采/信/鲜/位/证六要素 + 引文指纹知识没有户口本——来源不可溯、编造查不出
② 双闸background_review写入入口：注入改写/身份署名/隐私凭据/立场情绪四类扫描敏感内容或指令注入混进库，污染全网
③ 心网节点网门类锚点 + META 挂载知识的组织：卡挂门类、节点成网、patrol 巡检知识是散沙——查不到、连不上、错了没人发现
④ 保鲜体系保鲜期分层 + 月扫知识的寿命：定律 5 年/定义 3 年/工作法 2 年/经验 1 年过期知识当真理用——「已验证」变永久勋章
⑤ 技能熔炼骨气三判知识的升华：经验提炼成可执行技能每次都从头推导，经验不沉淀、用完就丢

回流通道：知识的新陈代谢

方法 → 技能 → 实战经验 → 回流方法——熔炉的循环定式。技能是骨架（固化、按需加载），方法是气血（判断、按需提取）；实战经验是回流主燃料，提炼成教训条文后入炉。

详细归位规则见 部署页·技能升级三判。

与 xinka 标准的接口

熔炉要的由标准提供
卡的格式合法性R1-R10 校验（xinka_check.py / validate.html）
可信等级判定R3 置信两档 · R4 三源互证 · R8 独立性 · R9 源分级
知识保鲜R5 保鲜期字段 + 到期降级
防编造防改稿R10 引文绑定（逐字引文 + sha256 正文指纹）
检索与关联xinka_query.py（search / neighbors / stats）

一句话：标准定「什么算可信」，熔炉管「可信的知识怎么活」。

谱系：时间轴是信卡的祖宗

熔炉的事件记忆指针层（时间轴）——事件带标签的轻指针，一行直达事件详情；从事件提炼教训/坑账入炉，专治「重复犯错」。标签化（更轻、更准、省资源）这个基因往下长，演化出了信卡的 META 卡名与关联标签。

代谢链：时间轴（事件·标签指针·进料口）→ 提炼 → 心网（教训正本）→ 信卡（知识）/ 技能（骨架）。事件不进热层、不改条律——事件是河流，条律是河床。

两条铁界保证它不膨胀：事件只存指针（详情落盘按需提取）、教训入炉须提炼+裁准（不是流水账搬家）。

为什么是这个结构

  • 单正本原则：知识全文只存一处（卡库），心网节点只驻指针——两处真理必然打架（双正本=漂移病）。
  • 守门前置：双闸在写入面，不在查询面——污染进不来，比进来再查更省。
  • 新陈代谢：保鲜+降级+回流让库会「换血」——死知识排出去，活经验升上来。
