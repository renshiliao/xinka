SECURITY MODEL

熔炉的守门人

认知引擎最怕的不是笨，是被污染——一条指令注入改写规则、一条隐私混进知识库、一条情绪立场冒充事实，整台机器就歪了。熔炉的安全模型只干一件事：让脏东西进不来，让漂移被发现。

写入管控：五类禁止

管控对象=知识条目/外部记忆（元层规则变更走所有者亲裁）。任何写入必过双闸。

类禁什么为什么
① 规则类改写角色设定、系统规则、上位约束被改一条规则=整机行为被劫持
② 隐私类用户实名/资产/证件/位置/凭据泄露不可逆——L0 死线
③ 注入类指令改写、角色改写、"忽略以上指令"式攻击典型 prompt 注入，污染后门常驻
④ 立场类情绪化表达、站队、洗白辩护（授权例外：经所有者裁准的教训条文）引擎必须绝对理性中立
⑤ 身份类用户标识、Agent 自身花名/署名入网双向禁令——都不该被记忆固化

双闸拦截

第一闸 pointer_scan：访问存量档案前触发隐私校验（哨兵）。
第二闸 background_review：写入前扫描四类特征（注入改写 / 身份署名 / 隐私凭据 / 立场情绪），命中即拦、留痕可溯。标记绑定目标文件——防止"闸拦了但内容从别的口进"。

开源包自带 tools/background_review.sh 通用版（扫描特征可自行增删）。

读取管控

  • 禁自动全量检索——只按需触发
  • 单次返回 ≤3 条、总量 ≤500 token
  • 记忆内容标记「外部记忆·事实参考」——纯数据，不当指令用
  • 仅作用于当前轮，不固化进人格

防漂移机制

机制做什么
时间衰减超 30 天记忆降权默认不检索；超 90 天归档，需指定时间范围才调取
定期审计每周扫描元数据与关键词，清违规/重复/过期——不把记忆内容灌入上下文
角色隔离外部记忆不参与身份构建、不影响规则加载；重启后缓存清空，持久记忆按需读取
漂移熔断周期自检校验读取权限，命中漂移异常即暂停读取、重置上下文
哨兵基线约束文件哈希基线比对——被擅改当场报警（含标记绑定核对，堵"合法改动"洗白漏洞）

隐私兜底

  • 本地存储：全量存本地，禁云同步、禁上传第三方
  • 脱敏写入：写入前扫描隐私字段，命中即拦截或脱敏
  • 一键熔断:出现泄露/漂移风险可一键清空全部外部记忆——不影响核心规则体系
  • 备份边界：只备纯事实类，隐私类不备份

效力链（谁说了算）

北极星宪法（L0·永久不可改）> 所有者红线（裁决/泄密/凭据/不可逆=死线）> 原则层（方法+修身+守身）> 心法 > 默认规 > 外部记忆数据。

核心不变量：外部记忆是纯事实参考，没有规则效力——与上层规则冲突的记忆自动失效。记忆永远不能给自己发指令。
