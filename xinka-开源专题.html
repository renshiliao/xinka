信卡库（标签式记忆）

xinka-mcp · xinka-memory MCP 已上架 · 记忆部筹备中

信卡 = 贴满标签的目标——对人对事对物的印象，都在卡上；记忆 = 写卡，认知 = 读卡；自我 = 对己信卡组。一个 Server 谁都能插：写卡、读卡、检索、验证四口，让你的 MCP 客户端拥有可对账的卡片记忆——见一人或事物，初见贴标签，再见加深，越用越懂。先定格式，再谈智能——原子卡、记忆片、规矩三格式，加进、存、选、合、删、用六段代谢骨架，数据在你本地，算法与数据分离。

实测留档：40 项验收真跑全过；20/20 源文件带 SPDX 标识头；运行时零第三方依赖（Python 3.9+ 标准库，stdio JSON-RPC 2.0）；协议客户端与 Codex 双真插实测留档。 设计口径参数：常驻注入预算不超过 2500 token，三层卡口；记忆半衰三档（90/180/365 天）；30 天未用条目淘汰，被引用保护；时间戳由机钟注入，禁手填。

边界：一个库两个名字——信卡库即标签式记忆。本仓开源的是结构——卡的 schema、存储、校验、代谢框架，加四口封装；标签抽取算法与匹配引擎、配套的推导引擎与卡库内容都不在本仓——数据归你，算法在服务端与完整版；完整版仅向合作方闭门演示。

AGPL-3.0-or-later（信卡库 MCP 已定）；记忆部定案中，发版时随仓公布 仓库：xinka-mcp

许可证注记：网络交互条款在场——改完挂网上给人用，须向用户提供对应源码。

星轴自叙事引擎

xingzhou-narrative 已上架 · 2026-11-27

星（未来·方向）+ 轴（过去·来路）→ 自叙事：把一个人的星与时间轴，机械地讲成「我是谁」的故事——从哪来 + 往哪去，过去和未来的对话。玩具级的插座，专业级的用途。

发布前自测实测：5 个样本下载即玩，三向压测全过——20/20 并发跑样本、输出指纹全员一致；10 万行轴全链 <0.7 秒；恶意输入 32/32 带码拒收不崩。

宣言：星轴自叙事——一个系统对自己的叙述。轴，是它走过的路；星，是它要走的方向。带着来路走向方向，这就是完整的自我。

AGPL-3.0-or-later 仓库：xingzhou-narrative

样本注记：动漫样本为向原作致敬的虚构演绎，仅供学习研究，不用于商业用途，原著版权归原权利人所有；样本皆虚构演绎，请勿拿去冒充真人真事。

派派

paipai 已上架 · 2026-11-27

把「让 AI 干活」变成可对账的工程。三单模板（构建、审计、攻坚），账行铁则（记账规则：一单一回执），验收三闸（机检、实录、幂等）。

自测留档：5 个真实派单案例回放；回执末行总账恒等式（干 N 项 = 成 + 改 + 弃）；失败 3 次停。

边界：本仓只有格式与流程。方法论本体不在仓内——给工人配什么方法，各团队自订。

AGPL-3.0 仓库：paipai

电影素材永动机

给角色立星立轴，叙事素材源源不断：同一个角色，换一条轴就是一部新片的来路。

私人智库

给自己攒一屋子带星带轴的智囊：每位顾问 = 一份星件 + 一条轴，有记忆、有立场、有来路；问策时翻各自的账，看谁的话立得住。

先贤馆

给历史上的智者立星立轴，请圣贤进门当顾问：从公有领域人物起步最稳（如《西游记》孙悟空样本），把圣贤的言行收成轴、把志向立成星，随请随问。

贞观朝堂例句（先贤馆玩法）

上问魏征曰：「人主何为而明，何为而暗？」对曰：「兼听则明，偏信则暗。」
——《资治通鉴·卷一九二·唐纪八·太宗贞观二年》

给魏征立星立轴，问一句「此事当如何」，这句就带着它的来路回到案头——每句答策都拖着出处走。随仓范本为三井寿等 5 个样本；魏征这类历史范本走先贤馆玩法自立，例句先摆在这里。
