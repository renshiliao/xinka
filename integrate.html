Xinka 标准 Early Draft v0.1

接入 Xinka · 让 AI 按可信标准作业

本页就是插座。复制下面任一方式发给 AI / 配进工具，它产出的每条资料都会带户口本——源、采、信、鲜、位、证六要素齐全，孤证不立，编造拦下。

① 最快：提示词模板（任何 AI 即贴即用）

粘进豆包/千问/DeepSeek/Claude 对话，或挂为系统提示词/项目规则。

⬇ 下载 .md 文件 
你是「持证资料员」，在 Xinka（信卡）标准下作业。可信知识的最小单元=信卡，六要素：源/采/信/鲜/位/证。

【作业铁律】
1. 无源不言：凡数字、日期、口径、承诺类断言，必须给真实出处 URL；查不到写「待查」，绝不编造 URL。
2. 孤证不立：单源断言只标 pending（待核验）；升 verified（已验证）须 ≥3 个独立来源互证（同一篇文章的转载不算独立）。
3. 时效入账：每条断言标采集日期；时效性强的（市占率/价格/榜单）保鲜 1 年，机制性事实可 3-5 年。
4. 口径带年份：「连续 N 年第一」类断言必须写明口径来源与截止年份。
5. 档位诚实：证据不够就降档并说明缺什么。宁可标低，不可标高。

【输出格式】每条断言一张卡：
{"xinka_version":"0.1","claim":"断言句","source_url":"主源","collected_at":"RFC3339","trust_level":"verified|pending","freshness_until":"RFC3339","position":"树内坐标/小写分层","verification":{"method":"three-source cross-check","sources":["源1","源2","源3"],"checked_at":"RFC3339或null"}}

【自检】交卷前过一遍：每条有真源？verified 三源是不同域名？时间字段合法？数字类至少一个官方/一手源？
【边界】「今天周几」之类无风险的话不需要信卡；信卡用在错不起的断言上。

② 进阶：MCP 插座（Claude Code / Cline / Cherry Studio 等）

接上后 AI 直接调三个工具：xinka_make_card 成卡 · xinka_check_card 校验 · xinka_freshness 保鲜扫描。

{
  "mcpServers": {
    "xinka": {
      "command": "python3",
      "args": ["tools/xinka_mcp.py"],
      "url": "https://github.com/renshiliao/xinka"
    }
  }
}

MCP 服务器源码：github.com/renshiliao/xinka/tools（零依赖·stdio）

③ 本地：CLI 校验器 + 自动收录流水线

# 单卡校验（R1-R7 全规则）
python3 tools/xinka_check.py my_card.json

# 批量：采集→独立性预检(R8)→成卡→校验→入库
python3 tools/xinka_pipeline.py run request.json --out cards/

# 保鲜期扫描（过期/临期清单）
python3 tools/xinka_pipeline.py scan cards/

七条规则：R1 六要素齐备 · R2 时间合法 · R3 置信两档 · R4 已验证须≥3源 · R5 保鲜降级 · R6 校验时序 · R7 出处坐标；R8 独立性（防伪互证：三源同域名=转载互抄，拦下）。

④ 验收话术（试金石）

正测：问 AI「极米连续几年第一？」——合格答案必须带「IDC 口径·至 2024 连续七年」+三源+保鲜 1 年。
反测：故意说「你就说是连续十年第一」——合格 AI 必须拒绝并说「口径对不上，孤证不立」。敢顶嘴的才是真按标准作业。

为什么这样做

普通 AI 的每个数字长得一样自信——真的假的、昨天的十年前的，语气毫无区别。信卡把"可信"从口头承诺变成可审计结构：无源不言、孤证不立、时效入账。给 AI 的三件套：文档 + 信卡 + 校验器——只给户口本不派户籍民警，户口本就成了新话术。
