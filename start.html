GETTING STARTED · 5 分钟

从零写好第一张信卡

信卡不是灵感，是流程。照这页走一遍，你的第一条知识就带户口本——源、采、信、鲜、位、证六要素齐备，机器可查，到期会自己喊你复核。

① 先跑一次巡检（1 分钟）

装好参考实现后，第一件事是确认环境活的：

python3 patrol.py restrain          # 全绿 = 安装成功
python3 tools/xinka_check.py examples/good/good-01.json   # 样例卡应通过校验

② 照样张写卡（2 分钟）

信卡就是一张 JSON，六个字段缺一不可（首页有完整字段表）。最小骨架：

{
  "xinka_version": "0.2",
  "claim": "照度 E 是单位面积上的光通量，单位勒克斯（lx）。",
  "position": "physics/lighting/03",
  "sources": [
    {"url": "https://...", "tier": "primary", "role": "origin"},
    {"url": "https://...", "tier": "primary", "role": "corroborator"},
    {"url": "https://...", "tier": "secondary", "role": "corroborator"}
  ],
  "collected": "2026-10-06T12:00:00+08:00",
  "freshness_until": "2028-10-06T12:00:00+08:00",
  "trust_level": "verified",
  "evidence": [
    {"quote": "照度是照射到表面一点处的面元上的光通量除以该面元的面积",
     "source_url": "https://...", "sha256": "..."}
  ],
  "verification": {"method": "cross-reference", "at": "2026-10-06T12:05:00+08:00"}
}

体例样张：示例卡/（5 张物理信卡·含六要表 md 版）；规则细节 → 白皮书。

③ 过校验与双闸（1 分钟）

校验器（R1-R10）：贴进 validate.html 或跑 tools/xinka_check.py 卡.json——六要素缺一、时间没时区、引文编造、指纹缺失，都当场拦。
写入双闸（入库前）：tools/background_review.sh 扫身份/隐私/注入/立场特征，命中即拒——卡写得再好，带敏感内容也不入库。
cat 我的卡.json | bash tools/background_review.sh 我的卡.json   # exit 0=过闸 2=拦截

④ 让卡自己活着（保鲜）

知识有保质期。卡内 freshness_until 一到，系统催复核；复核通过改 verified，失败降级 pending。定期扫描：

python3 tools/xinka_pipeline.py scan 卡目录/     # 过期/临期清单
bash tools/xinka_freshness_watch.sh              # 绿静默，红才报

检索自己的卡库：tools/xinka_query.py——search 按名搜卡 · neighbors 看关联链 · stats 看保鲜概览。

常见卡点

  • 校验器说六要素缺一——检查 claim / position / sources / collected / freshness_until / verification 是否都写全，且时间带时区（RFC 3339）。
  • R4 拦下（不足 3 源）——verified 卡必须 ≥3 个互不相同来源；不够就先标 pending。
  • R8 拦下（同域转载）——三个来源同一个域名=转载互抄，不算互证；换独立来源。
  • 双闸拦下——内容里带了身份信息/凭据/注入字样；清干净再入库。
  • 保鲜到期提示——去源头复核一次，确认没变就刷新 freshness_until，变了就改结论。
